# Известные требования

Дата исходного контекста: 2026-10-08. Документ фиксирует требования из текущего
запроса и архитектурные следствия. Полное исходное ТЗ не предоставлено; этот
документ не является его заменой. Предложения и неуточнённые функции отмечены явно.

## Назначение и среда

- Локальное desktop-приложение для длинных OBS-видеозаписей и аудиофайлов.
- Результат — структурированный, читаемый русский текст.
- Windows 11, NVIDIA RTX 4060 Ti 8 GB, локальная PostgreSQL.
- Без платных API и облачной обработки.

## Известные функциональные требования

| ID | Требование |
| --- | --- |
| F-01 | Принимать существующий локальный видео- или аудиофайл, включая записи OBS. |
| F-02 | Исследовать медиа через ffprobe и извлекать/подготавливать аудио через FFmpeg. |
| F-03 | Распознавать русскую речь локально через faster-whisper / CTranslate2. |
| F-04 | Использовать Silero VAD для определения интервалов речи. |
| F-05 | Преобразовывать результат в читаемый структурированный текст с сохранением исходного результата распознавания. |
| F-06 | Предоставлять desktop-интерфейс на PySide6; тяжёлое распознавание выполнять в отдельном процессе. |
| F-07 | Использовать локальную PostgreSQL для метаданных задач и текстовых результатов; схему изменять через Alembic. |
| F-08 | Предусмотреть экспорт результата в локальные файлы; форматы требуют уточнения. |

Метаданные сегментов и временные отметки нужны для связи текста с исходным медиа;
их точная схема проектируется позже. Диаризация, редактор текста, поиск,
пакетная обработка, резюмирование и локальная LLM не считаются согласованными
функциями этого этапа.

## Нефункциональные требования

| ID | Требование |
| --- | --- |
| N-01 | Обработка и хранение пользовательского содержимого локальны. Аудио, видео и транскрипты не передаются во внешние сервисы. |
| N-02 | Приложение не должно требовать платных или облачных AI API. |
| N-03 | Длинные записи обрабатываются потоково/чанками. Использование RAM и очередей ограничено; целый медиафайл не читается в память. |
| N-04 | Настройки модели и вычислений должны учитывать 8 GB VRAM. Размер модели, precision и batch size выбираются по измерениям, без обещаний скорости. |
| N-05 | GUI сохраняет отзывчивость. CUDA и модель распознавания принадлежат отдельному GPU worker. |
| N-06 | Секреты не попадают в код, Git, IPC-события и логи. PostgreSQL хранит ссылки на исходные медиа, а не их содержимое. |
| N-07 | Архитектура — модульный монолит, src-layout; публичные интерфейсы типизированы, новая бизнес-логика покрывается тестами. |
| N-08 | Ошибки worker и внешних инструментов явно сообщаются; частичная обработка не выдаётся за успешно завершённую. |
| N-09 | Исходные пользовательские файлы не изменяются и не удаляются автоматически. Временные данные принадлежат приложению. |
| N-10 | Зависимости и модели версионируются воспроизводимо после проверки совместимости; конфигурация отделена от кода. |

Прогресс, отмена, восстановление после сбоя и повторный запуск предусмотрены
архитектурой. Точные пользовательские сценарии и политика восстановления ещё
не утверждены. Численные SLA по времени, RAM и качеству не заданы.

## Планируемый стек

Python актуальной стабильной ветки; SQLAlchemy актуального стабильного выпуска
на момент подключения; PostgreSQL, Alembic, Pydantic Settings, FFmpeg/ffprobe,
faster-whisper / CTranslate2, Silero VAD, PySide6, pytest, Ruff, uv.

На этапе 0 выбран базовый Python >=3.14 и проверен установленный 3.14.4.
Это не подтверждение совместимости CUDA-стека и не фиксация навсегда.
Runtime-зависимости пока не объявлены. Конкретные совместимые версии и
`uv.lock` фиксируются при их подключении; prerelease автоматически не выбирается.

## Граница текущего этапа

Только документация, правила агента, .gitignore, pyproject.toml, минимальное
обозначение будущего пакета и каталога тестов. Без транскрибации, GUI,
репозиториев PostgreSQL, миграций, IPC, обработки текста и других реализаций.

## Требует уточнения

- Длительность и размер типичных записей, контейнеры/кодеки OBS, аудиодорожки,
  смешанная речь и требования к выбору дорожки.
- Что означает «структурированный текст»: абзацы, заголовки, временные отметки,
  степень редактирования; допустимая потеря/изменение исходной формулировки.
- Нужны ли диаризация, редактирование, очередь файлов, отмена и восстановление.
- Форматы экспорта, требования к сохранению и срокам хранения результатов.
- Критерии качества и производительности, допустимый CPU fallback.
- Модель, precision, CUDA/cuDNN, драйвер и совместимые версии Python/библиотек.
- Версия и конфигурация локальной PostgreSQL, драйвер, схема и правила доступа.
- Пути моделей/данных, установка приложения и загрузка моделей.

Загрузка зависимостей/моделей при подготовке среды отделена от обработки:
пользовательское содержимое не отправляется; автоматическая загрузка моделей
при запуске обработки пока не согласована.
