# Журнал архитектурных решений

Начальные решения от 2026-10-08. «Принято» относится к направлению архитектуры,
не означает реализацию. Изменения фиксируются новой записью со ссылкой на
заменённое решение.

| ID | Решение | Статус | Обоснование |
| --- | --- | --- | --- |
| ADR-001 | Модульный монолит с UI, Application, Domain и Infrastructure. | Принято | Единое локальное приложение; слои отделяют бизнес-правила от Qt, БД и движка. |
| ADR-002 | src-layout, пакет local_transcriber, tests/ в корне Transcribation/. | Принято | Явная упаковка и граница исходников; тесты не входят в runtime-пакет. |
| ADR-003 | GPU worker отдельно от GUI, Windows spawn, ограниченный локальный IPC. | Принято | Отзывчивость UI, владение CUDA в одном процессе, ограничение памяти и изоляция сбоев. DTO и тайм-ауты уточняются позже. |
| ADR-004 | Один GPU worker и одна активная задача распознавания на старте. | Принято | 8 GB VRAM не следует занимать несколькими копиями модели. Расширение требует измерений. |
| ADR-005 | Потоковая/чанковая обработка медиа и ограниченные очереди результатов. | Принято | Длительность записи не должна определять объём RAM; нужны обратное давление и корректные временные отметки. |
| ADR-006 | PostgreSQL хранит метаданные и тексты; медиа и модели — в файловой системе. SQLAlchemy и Alembic — адаптер хранения и миграции. | Принято | Большие бинарные файлы не раздувают БД; схема меняется воспроизводимо. Версия и драйвер ещё не выбраны. |
| ADR-007 | Исходные сегменты распознавания сохраняются отдельно от производного текста. | Принято | Возможны повторная обработка и проверка преобразований без повторного распознавания. |
| ADR-008 | Обработка полностью локальна, без платных/облачных AI API. | Принято | Прямое требование пользователя; аудио, видео и транскрипты не передаются наружу. |
| ADR-009 | uv, pytest, Ruff; Hatchling для упаковки. Runtime-зависимости подключаются по этапам. | Принято | Минимальная подготовка без CUDA и моделей. Dev-группа отделена; uv.lock фиксируется после реального разрешения зависимостей. |
| ADR-010 | На этапе 0 базовый Python >=3.14, Ruff target py314. | Принято для этапа 0 | Проверен локальный Python 3.14.4. Полный стек пока не проверен: текущую стабильную версию и совместимость Windows/CUDA сверить перед подключением движка. Изменение минимальной версии требует новой записи. |
| ADR-011 | Будущая единая точка входа local_transcriber.__main__:main; src/main.py сохраняется как будущий делегирующий launcher. | Принято | Сохраняет пользовательский файл и исключает дублирование bootstrap. Пока ни launcher, ни console script не реализуются. |
| ADR-012 | Перенести .git из Transcribation/src/ в Transcribation/. | Выполнено с разрешения пользователя | Фактический Git-корень не соответствовал заданному src-layout. При переносе история, remote и индекс сохранены; commit и push тогда не выполнялись. Последующая фиксация структуры и отправка в origin/main отдельно разрешены пользователем. |

## Границы и отложенные решения

- Модель, precision, batch size, CUDA/cuDNN, CPU fallback и конкретные версии
  тяжёлых зависимостей выбираются после отдельной проверки совместимости.
- Форматы экспорта, правила структурирования текста, схема БД, детали IPC,
  UI и распространение приложения пока не утверждены.
- Тесты появятся вместе с реальной логикой; пустой этап не получает фиктивные
  реализации и тесты ради успешного статуса.
